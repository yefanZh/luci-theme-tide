## 已核对的上游接口

- header / footer / sysauth 模板环境及 ui.menu.getChildren()。

## 本地证据

7 项基础检查与 13 项浏览器交互检查全部通过；浏览器控制台无未处理异常。中文 PO 经 msgfmt 检查并用 LuCI 上游 po2lmo 转换为 LMO。

- 四个正式模板通过原生 ucode 编译及渲染。
- 主题注册脚本通过 shell 语法、首次注册和重复注册测试。
- Makefile 使用一次 LuCI 构建规则，包生成只调用一次。
- SDK feed 将提交的源码放到 luci-theme-tide 子目录。回归检查使用 OpenWrt 扫描器相同的路径提取规则，避免根目录 Makefile 被误解析而缺少 feed 索引。
- 修复 feed 目录后，x86_64 SDK 的实际构建已经成功；打包日志确认主题与中文翻译均为 arch:noarch，未上传 SDK 构建的 x86 依赖包。随后工作流切换至 ARM64 SDK 复验；Release 将采用该 ARM64 构建产物。
- 浏览器测试使用上游 LuCI DOM 工具与 mock RPC，不是路由器上的真实后台。
- 明暗同 DOM、同尺寸、同输入；快速切换无未处理的过渡取消异常。
- 45 个插件菜单、深层分组、长中文标题、权限过滤、中部滚动、设备信息固定。
- 设备过滤空状态、清除筛选、详情抽屉、Escape 关闭、轮询后焦点恢复。
- 刷新失败保留旧数据、重试清理错误、采样暂停、断开的 WAN、计数器重置。
- 320、390、680、768、980、1024、1280、1440、1920px 明暗总览及宽插件表单，无整页横向溢出。
- 手机导航限制背景操作、键盘焦点循环、遮罩 / Escape / 选页关闭。
- 跟随系统、减少动态效果、动效暂停、偏好持久化；320px 禁用 JS 登录页仍可提交。
- 字体失败有系统回退；不依赖外部字体资源。
- 设备名称经文本节点渲染，带 HTML 的主机名不会产生 DOM 注入。

浅色警告色从原型的 #a66445 加深到 #995b3f：对工作区背景 4.93:1、选中色面 4.67:1、白面板 5.35:1。其余主要颜色保留设计规范中的数值；普通文字至少 4.5:1，上传图线至少 3:1。

## 实机验收仍需完成

本地 mock、模板编译和 SDK 构建不等于真实设备验收。尚未连接用户路由器，应在安装后核对：

1. 25.12 的登录、真实 RPC、WAN / IPv6 / 无 WAN、无无线硬件及受限账户。
2. 已安装插件的表单、接口编辑、无线设置、日志、保存应用和断线回滚。
3. 实际浏览器与设备上的最终视觉、触摸、字体回退和菜单状态恢复。

主题不接管原生提交逻辑；真实保存结果和回滚状态继续由 LuCI 显示。

## 设计检测复核

已修正三项检测提示：状态提示框移除 3px 单侧强调线；原生 LuCI 进度条移除额外的宽度过渡；澜内存条改用 scaleX，保留 850ms 入场与 350ms 更新时序。没有增加检测忽略规则。

同一 Chromium 测试夹具中，内存条两次更新的 LayoutCount 从 84 降为 0。此结果仅说明该控件动画减少了布局计算，不代表实机整体性能。变更文件的 Impeccable 检测结果为空。
